# 2026ドラフト候補選手JSON仕様（T1-1）

`data/draft-2026-candidates.json` は「12球団1位指名予想」機能（draft-predict.html）が
選手選択リストとして読み込むファイル。

## フォーマット

```json
{
  "version": "2026-09-27",
  "players": [
    { "id": "c001", "name": "織田翔希", "org": "横浜高", "category": "高校", "pos": "投手", "featured": true },
    { "id": "c033", "name": "星野世那", "org": "大商大", "category": "大学", "pos": "", "featured": true }
  ]
}
```

## フィールド

| フィールド | 必須 | 内容 |
|---|---|---|
| `version` | 必須 | この候補リストの版を表す文字列（更新日でよい）。予想の保存データと突き合わせて、リストが差し替わっていないかT2-1（答え合わせ機能）で確認するのに使う |
| `players[].id` | 必須 | 候補選手ごとの一意なID。`c001`のように`c`+3桁連番を推奨。**一度割り当てたら変更しない**こと（変更すると、既にこのIDで保存されているユーザーの予想が壊れる） |
| `players[].name` | 必須 | 選手名 |
| `players[].org` | 必須 | 所属（高校名・大学名・社会人チーム名・独立リーグ球団名など） |
| `players[].category` | 必須 | 区分。`高校` / `大学` / `社会人` / `独立リーグ` のいずれか。`独立リーグ`は画面上「独立リーグ・その他」と表示される（`draft-predict.html`内の`CATEGORY_LABELS`でマッピング。データ側の値は`独立リーグ`のまま） |
| `players[].pos` | 必須（空文字列可） | ポジション（投手・捕手・内野手・外野手）。**ポジション未確定の選手は空文字列`""`にする**（画面には「未定」のような文言を出さず、単に表示を省略する仕様） |
| `players[].featured` | 必須 | `true`/`false`。`true`は「注目選手」として初期表示される。`false`は「全候補を表示」ボタンを押したときだけ選択肢に出る |

**能力値・評価点は含めない**（CLAUDE.mdの方針どおり、アマチュア選手に数値評価は付けない）。

## 画面側の絞り込み機能

`draft-predict.html`は以下の絞り込みUIを持つ：

- **区分フィルター**：`category`で絞り込み（すべて／高校／大学／社会人／独立リーグ・その他）
- **ポジションフィルター**：`pos`で絞り込み（すべて／投手／捕手／内野手／外野手）
- **全候補を表示ボタン**：既定では`featured: true`の選手のみを選択肢に表示し、ボタンを押すと`featured: false`も含めた全選手が選択肢に加わる

すでに予想として選択済みの選手は、フィルターで絞り込まれて選択肢から外れても選択状態自体は保持される
（選択肢の先頭に一時的に差し込まれる）。

## 選手を追加する方法

1. `players`配列の末尾に、次の連番のIDで1件追加する（例：既存が`c109`まであれば`c110`から）
2. 既存選手の`id`・`name`は変更しない（特に`id`は保存済みの予想と紐づいているため厳禁）。
   `org`・`category`・`pos`・`featured`は、情報が更新された場合（進路変更・ポジション確定など）は書き換えてよい
3. 選手を削除する場合も、`id`は再利用しない（欠番のまま次のIDから採番する）
4. リストを大幅に入れ替えるなど、既存の予想に影響しうる変更をした場合のみ`version`を更新する日付に変える
5. ポジションが未確定の選手は`pos`を空文字列にしておき、確定次第、値を埋める（`id`は変えない）

## ドラフト後の扱い（T2-4との関係）

指名された候補選手を`initialDatabase`（プロ選手データ）に本採用する際は、CLAUDE.mdの既存ルールどおり
週刊ベースボールONLINEの実在選手ページIDを新たに割り当てる。ここでの`c001`のような仮IDとは別物で、
そのまま転用しない。
