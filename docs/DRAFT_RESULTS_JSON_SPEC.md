# 2026年ドラフト実際の指名結果JSON仕様（T2-1 事前準備）

`data/draft-2026-results.json` を用意すると、`draft-predict.html`に「答え合わせ」セクションが
自動的に表示されるようになる。**このファイルが存在しない間は、答え合わせ機能はページに一切表示されない**
（`fetch`が404で失敗した場合は答え合わせ用のUI自体を描画しない実装にする）。

## いつ・何を入力するか

10月22日のドラフト会議当日の夜、12球団の**1位指名で実際に名前を呼ばれた選手**を入力する。
「予想」が対象にしているのは"どの選手を1位で指名したか"であり、抽選の勝ち負けそのものではないため、
**競合の末に外れた球団も、最初に指名した（くじを引いた）選手の名前を`name`に入れる**。
外れくじの末に代わりに獲得した選手（いわゆる「外れ1位」）は、任意項目の`fallback`に記録する
（的中判定には使わず、結果画面での表示にのみ使う）。

## フォーマット

```json
{
  "version": "2026-10-22",
  "updatedAt": "2026-10-22T21:30:00+09:00",
  "picks": {
    "巨人": {
      "name": "織田翔希",
      "org": "横浜高",
      "pos": "投手"
    },
    "阪神": {
      "name": "鈴木泰成",
      "org": "青山学院大",
      "pos": "投手",
      "competedWith": ["西武"],
      "lottery": "won"
    },
    "西武": {
      "name": "鈴木泰成",
      "org": "青山学院大",
      "pos": "投手",
      "competedWith": ["阪神"],
      "lottery": "lost",
      "fallback": { "name": "○○○○", "org": "○○高", "pos": "捕手" }
    }
  }
}
```

## フィールド

| フィールド | 必須/任意 | 内容 |
|---|---|---|
| `version` | 必須 | 結果データの版（日付でよい）。予想機能側の`data/draft-2026-candidates.json`とは別物で、突き合わせには使わない |
| `updatedAt` | 必須 | 入力日時（表示用） |
| `picks` | 必須 | 12球団分のオブジェクト。**単独指名の球団は`name`・`org`・`pos`の3項目だけでよい**（最小構成） |
| `picks[球団].name` | 必須 | 実際に1位で入札を発表した選手名（＝抽選の結果に関わらず、最初に名前を呼ばれた選手）。表記ゆれの吸収方法は下記「名前の照合方法」を参照 |
| `picks[球団].org` | 必須 | 所属（高校・大学・社会人など） |
| `picks[球団].pos` | 必須 | ポジション |
| `picks[球団].competedWith` | 任意 | 同じ選手を1位指名した他球団名の配列。競合がなければ省略してよい |
| `picks[球団].lottery` | 任意 | 競合があった場合のみ：`"won"`（交渉権獲得）または`"lost"`（外れ） |
| `picks[球団].fallback` | 任意 | `lottery: "lost"`の場合のみ：外れ1位で実際に指名した選手（`name`/`org`/`pos`の3項目）。的中判定には使わない、表示専用の情報 |

**12球団すべてに`picks`のエントリが無くても動作する**（欠けている球団は「未入力」として不一致扱いになる）。
全球団揃うまで待つ必要はなく、分かった球団から追記していってよい。

## 入力例（最小構成・競合なしの場合）

```json
{
  "version": "2026-10-22",
  "updatedAt": "2026-10-22T21:00:00+09:00",
  "picks": {
    "巨人": { "name": "選手名", "org": "所属", "pos": "投手" }
  }
}
```

この1球団分だけでもファイルとして有効。残り11球団は分かり次第追記していけばよい。

## 名前の照合方法（表記ゆれ対策）

当日の手入力ミスで「本当は当たっているのに外れ扱い」にならないよう、比較前に次の正規化をかけてから
文字列を比較する（`draft-predict.html`内の`normalizeName()`）。

1. 前後・途中の空白（半角スペース・全角スペース`　`）をすべて削除する
2. 一部の異体字を統一する（対応表は`CHAR_VARIANTS`という1つのオブジェクトにまとまっており、
   新しい異体字が見つかったら1行足すだけで追加できる）。現時点の対応：
   `邉`・`邊`→`辺`、`髙`→`高`、`﨑`→`崎`、`濵`→`浜`、`德`→`徳`

正規化後に文字列が完全一致すれば「同じ選手」とみなす。読み仮名や旧字体・新字体の細かい違いまでは
吸収しないため、`name`にはできるだけ一般的な表記（プロ入り後に報道で使われる表記）を入力すること。

## 答え合わせの判定方法（2段階）

判定は次の2種類を独立して数える。どちらも`data/draft-2026-results.json`側に追加の項目は不要で、
既存の`name`（最初の入札選手）と`fallback`（外れ1位で獲得した選手）だけで両方を算出できる。

| 判定 | 意味 | 使う値 |
|---|---|---|
| 🎯 1位入札的中 | 予想した選手に、その球団が最初に1位で入札したか（**抽選で外れても的中**） | `picks[球団].name` |
| 🏆 交渉権獲得的中 | 抽選も含めて、その球団が実際に交渉権を獲得した選手と一致するか | `lottery: "lost"`なら`fallback`、それ以外は`name` |

称号（`TITLE_TIERS`）は🎯1位入札的中の数で決まる。🏆交渉権獲得的中は称号とは別に、サブ情報として
件数のみ表示・シェア画像に掲載する。

最小構成（`name`/`org`/`pos`の3項目だけ）の球団は、`lottery`が無いので🎯と🏆は常に同じ判定になる
（＝競合が無かった球団として扱われる）。競合があった場合だけ`competedWith`・`lottery`・（外れの場合）
`fallback`を追加すればよく、それ以外の入力は増えない。

**外れくじが2回以上続いた場合（いわゆる「外れ外れ1位」）も、スキーマ変更は不要**。`fallback`は
「間に何回外れを挟んだか」を記録する項目ではなく、「最終的に交渉権を得た選手」を入れる項目として
設計してあるため、外れが何連続しても`fallback`には**最後に実際に交渉権を得た選手**をそのまま
入力すればよい（2回目の外れくじの相手になった選手を経由地点として記録する必要はない）。この挙動は
テスト用結果ファイルで実際に確認済み（`name`＝最初の入札選手への的中は🎯として維持されつつ、
2回外れた末の最終獲得選手への的中が🏆として正しく判定される）。

## 答え合わせの表示ロジック（実装済み）

- `draft-predict.html`は`data/draft-2026-results.json`の取得を試み、**404などで取得できない間は
  答え合わせセクションを一切表示しない**（ファイルを置いた瞬間に表示され始める）
- テスト用のリハーサルでは、本番ファイルの代わりに`data/draft-2026-results.test.json`を読み込む
  `?test_results=1`というURLパラメータが使える（詳しくは`docs/DRAFT_DAY_RUNBOOK.md`参照）。
  本番ファイル名を書き換える必要はない
- 保存済みの予想（localStorageの`draftPrediction2026`）と`picks`を球団ごとに突き合わせ、
  上記の正規化＋2段階判定で的中を数える
- 12球団中の🎯1位入札的中数に応じて称号を表示し、結果をシェア画像として保存・投稿できる
  （的中数の区分・称号名は`draft-predict.html`内の`TITLE_TIERS`を参照。デザイン変更は
  コードの数値を書き換えるだけでよい）

## 今後の拡張（T2-2との関係）

的中率ランキングをオンライン化する場合は、この結果JSONを正としてサーバー側でも同じ判定ロジックを
再利用できるよう、正規化ルール（`CHAR_VARIANTS`）と2段階判定の基準を変えないことを推奨する。
